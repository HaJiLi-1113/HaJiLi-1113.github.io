用easy-java生成的代码

  1. ABaseController

    它是所有控制器的基类
    基础配置和依赖
    继承自 Object 类，作为所有控制器的父类
    注入了 RedisComponent 组件用于处理 Redis 相关操作
    定义了两个状态常量：
    STATUC_SUCCESS: “success”
    STATUC_ERROR: “error”
    响应构建方法
    getSuccessResponseVO(T t):
    构建成功的响应对象
    设置状态为 STATUC_SUCCESS
    返回 200 状态码和对应信息
    getBusinessErrorResponseVO(BusinessException e, T t):
    构建业务异常响应
    如果异常中没有指定错误码，则使用 600 错误码
    getServerErrorResponseVO(T t):
    构建服务器内部错误响应
    使用 500 错误码
    工具方法
    getIpAddr():
    获取客户端真实 IP 地址
    考虑了多种代理情况，包括 x-forwarded-for 等头部信息
    savetoken2Cookie(HttpServletResponse response, String token):
    将 token 保存到 Cookie 中
    设置过期时间为 7 天
    getTokenUserInfoDto():
    从请求头中获取 token 并查询用户信息
    cleanCookie(HttpServletResponse response):
    清除 Cookie 中的 token 信息
    同时清理 Redis 中的 token 数据
    这个基类提供了统一的响应格式、用户认证支持以及 IP 获取等通用功能，方便子类控制器使用。

  2. AGlobalExceptionHandlerController

    类功能概述
    类名: AGlobalExceptionHandlerController
    作用: 全局异常处理器，用于统一处理系统中未被捕获的异常
    继承关系: 继承自 ABaseController
    注解: 使用 @RestControllerAdvice 标识为全局异常处理类
    核心组件
    日志记录: 使用 LoggerFactory 创建日志记录器
    异常处理方法: handleException 方法处理所有类型的异常
    异常处理流程
    日志记录:
    记录请求URL和完整的异常堆栈信息
    异常分类处理:
    NoHandlerFoundException: 404错误处理
    BusinessException: 业务异常处理
    BindException/MethodArgumentTypeMismatchException: 参数类型错误
    DuplicateKeyException: 数据库主键冲突
    ConstraintDeclarationException: 约束声明异常
    其他未分类异常: 默认500服务器错误
    响应构建:
    所有异常最终封装为 ResponseVO 对象返回
    根据不同异常类型设置相应的错误码和错误信息
    特点
    统一了系统的异常响应格式
    提供了详细的异常分类处理逻辑
    通过继承 ABaseController 获得了基础的响应构建能力（如 STATUC_ERROR 常量）
    使用了 ResponseCodeEnum 枚举来管理错误码

  3. exception包
    exception 包提供了自定义的异常类，用于处理业务逻辑中的异常情况。

  4. entity 包
    entity 包提供了数据模型类，用于定义系统的数据结构。

  5. service 包
    service 包提供了业务逻辑层，用于处理业务逻辑。

  6. util 包
    util 包提供了工具类，用于提供公用的方法和工具类。
